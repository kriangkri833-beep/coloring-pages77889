# Existing Etsy Draft Workflow — Input Contract

**Date inspected:** 2026-11-18
**Source:** `D:\BeingBrightstuioproduct\scripts\etsy_api\` (`etsy_upload.py`, `README.md`). Read only; nothing in that system was changed.
**Purpose:** Document what the existing system actually accepts, before any adapter is designed (plan section 5 / task 2).

## What it does

Creates an Etsy **draft** listing through Etsy Open API v3 from one `listing.json`, then uploads images, download file(s) and an optional video. It never publishes; the owner reviews and publishes in Etsy. Run either with `python scripts/etsy_api/etsy_upload.py <path>/listing.json` or through the local panel (`run_ui.bat`, http://localhost:8765).

## listing.json fields

| Field | Required | Notes |
|---|---|---|
| `title` | yes | Used as is |
| `description` | yes | Used as is |
| `price` | yes | Number, USD |
| `taxonomy_id` | yes | Script refuses if missing. Find ids: `python etsy_upload.py --taxonomy "<word>"`. Previous products used 1874 (Templates). Correct id for coloring pages is **not yet verified**. |
| `tags` | no | Max 13, each max 20 characters, else the script exits |
| `quantity` | no | Default 999 |
| `who_made` | no | Default `i_did` |
| `when_made` | no | Default `2020_2026` |
| `images` | no | Paths relative to `listing.json`; the script uploads the first 10 only |
| `files` | no | Digital download file(s), paths relative to `listing.json` |
| `video` | no | One mp4, 5–15 s, max 100 MB (the owner has used longer ones on Etsy, see project notes) |
| `etsy_listing_id` | written back | Set after creation; a second run refuses unless `--force` |

Fixed by the script: `type=download`, `is_supply=false`.

## Where it expects the folder

`products/<name>/` in the main repo or `D:\BeingBrightStudio_out\<name>\`. The panel lists every folder containing a `listing.json` there. Coloring-pages output is not in either location yet.

## Limits to respect (from README, partly unverified)

- 13 tags, 20 characters each.
- Images: README says up to 20 on Etsy, but the script uploads only 10.
- Download files: up to 5 files, 20 MB each (per README). A multi-hundred-page Letter + A4 bundle may need splitting.
- No bulk creation of dozens of listings at once.

## Gaps relative to the plan

1. **No section field.** `etsy_section` in the plan has no counterpart; shop sections are not set by this script.
2. **No AI-disclosure field.** The README says to check `who_made` and the AI-disclosure answer in the draft by hand before publishing. Images generated by ChatGPT should be reviewed against Etsy's current creativity/AI rules by the owner.
3. **No digital-download disclosure or print-size fields.** These must go in `description` text.
4. **Image cap of 10** is lower than Etsy's limit.
5. **No status/READY flag.** The plan's READY gate lives outside this system; the adapter must only write `listing.json` for READY products.

## Adapter implication (not built)

The simplest safe adapter writes a valid `listing.json` plus `images/` and a `.zip` into a folder under `D:\BeingBrightStudio_out\<product>\` from an approved manifest, then lets the existing panel or script create the draft. This needs no change to the existing system. To be confirmed with the owner before any development.
